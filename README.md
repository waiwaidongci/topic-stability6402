# 字岑展览语义主题册

字岑策展文本研究组的 15 位编辑需要把匿名、已分词的展签摘要整理成可审阅的主题册。上游提供 `zc-exhibition-tokens-2026.jsonl`，下游得到人工命名的主题与已确认编辑说明 CSV。项目处理关键词堆叠忽略混合内容、重复初始化改变主题顺序、重建误差被误读为语义质量这三个问题。馆藏扩到百万篇后，同一语料按批追加导入，计算进程限制 512MiB 内存，词频与筛词仍按全库统计，不抽样不截断。

这是固定种子的合成场景，不含真实观众或作品身份。初始 360 篇文档约 50 词、四组混合内容，其中刻意包含空文本、全部非白名单词、低频词样本。默认 K=4、5 次初始化得到 357 篇有效文档、49 词。实际参考相对重建误差约 0.4959007151；其值不代表主题语义正确率。

## 编辑的一天

1. 09:00，主题研究编辑周宁登录研究首页，读“稳定的词组，也需要人来读”。
2. 在“分词语料”核对 `秋季展签分词摘要 · 360篇` 的 reference、标题与空白分词文本；文档按页翻阅、按编号前缀查找，可先建空语料再按批（每批≤1000篇）追加到同一语料，批内或库内 reference 重复整批拒绝。
3. 在“主题配置”预先决定 K=4、初始化重复 5、seed=221、min_df=2、max_iter=2000 和 tolerance=0.0001，再送入队列。K 是编辑研究选择，不自动按跨 K 的重建误差下降选优。
4. 在“词权与稳定”选择任务，查看冻结输入指纹、357 有效文档、3 个排除理由、词汇和 IDF。5 次真实拟合使用 seed 221–225，各自保存迭代数与重建误差；逐篇激活与排除原因按展签编号分页翻查每次初始化。
5. 读主题词权与代表文档的相对激活，将“待命名主题01”改为自己的编辑名称，并留下命名依据。名称由人工输入，程序没有语义真值标签。
6. 对齐表展示每次独立拟合相对于第 0 次拟合的 Hungarian 匹配、每主题余弦相似度和原始匹配编号。第 0 次是预先固定参考，不是按误差挑选的赢家。
7. 在“编辑审阅”选择主题、写解释和后续核对行动，创建编辑说明。说明冻结所选主题的名称、词权、相似度快照。
8. 负责人 admin 阅读后确认或退回。viewer 只能下载已确认说明 CSV。后续修改实时主题名不会改写已经审阅的快照。
9. 在“成册留痕”核对导入、任务、命名、说明、审批与导出审计；每个请求携带 X-Request-ID。

## 数值口径

- 分词仅使用 `str.split()` 空白切分，严格匹配 `backend/src/constants/vocabulary.py` 的 50 词白名单。没有自动中文分词或词义扩展。词汇从所选语料按 min_df 筛选并排序；保存词汇、df、IDF 和全部参数。
- 计算分两遍流式扫描同一语料（每批 5000 篇，按展签编号二进制升序）：第一遍只累计全库 df 并同步计算冻结输入指纹，第二遍逐行构造 TF-IDF 写入文件支撑的 float64 memmap。TF 是原始词频；`idf(t)=ln((1+n)/(1+df(t)))+1`；每篇 TF-IDF 向量 L2 归一。n 包含所选空文档。白名单或 min_df 后零行从 NMF 排除，理由单独保留，不悄悄删去 IDF 样本。df、筛词、IDF 始终按全库统计，不抽样、不截断。
- NMF 与 sklearn 的 random 初始化、coordinate descent、Frobenius 目标、无正则、固定 random_state 同一口径；拟合循环直接驱动 sklearn 的 `_update_coordinate_descent`，X 只参与稀疏点积不做全量物化复制，单次 W 逐次落盘，单进程匿名内存峰值约 180MiB（百万篇实测），worker 容器限制 512MiB。用户选择 K∈[2,6]，重复 5–10 次。每次都真实拟合；任一次未收敛即任务失败，不拼成虚假稳定结果。小语料上词权、激活、迭代数与原一次性计算逐位一致，重建误差差异不超过 4e-15（远低于百万分之一口径）。
- H 每行 L1 归一时，W 同列乘以原 H 行和，所以 WH 不变。保存每次原顺序和对齐后的 H、seed、迭代、重建误差、余弦矩阵、置换与各主题相似度；逐篇保存每次初始化的原始 W 行，按展签编号分页提供。
- 归一 H 通过 L2 余弦与 Hungarian 一对一最优匹配。平均稳定性只统计非参考重复，避免把参考自身的 1 加入均值。相似度量化初始化敏感性，不等于语义真值；相近或简并主题的匹配可能不唯一。
- 文档展示 W 与 `W_i/sum(W_i)` 的相对激活。这是归一后的模型强度，不是概率后验。H 词权也不是词义置信度。
- 有限非负矩阵、K 不超文档数/词数且不超数值秩（绝对容差 1e-10；大矩阵在文件支撑副本上以同一 gesdd 奇异值判定）。常量/低秩、空词汇、空主题与未收敛均明确失败。不同 K、词汇、min_df 的误差不直接比较语义质量。
- MySQL 使用 DOUBLE，SQLAlchemy 设置 `asdecimal=False`，避免默认 Decimal 结果的十位小数转换损失；API 测试将持久化主题均值与逐次余弦重新计算比较到 1e-12。

## 结构

78 个有职责的 Python/TypeScript/Vue/CSS 源文件（不含空包、依赖和编译产物）。六个业务页面为研究首页、分词语料、主题配置、词权与稳定、编辑审阅、成册留痕。业务实体 Corpus → TokenDocument → TopicRun → RunDocument/TopicProfile → EditorialNote，另有 User/AuditLog。路由、schema、服务、ORM、前端 API/store 和页面形成完整链路。

后端枚举位于 `src/constants/enums.py`，前端对应 `src/constants/enums.ts`。RequestID 与 Error 两个中间件统一请求追踪和错误边界。TopicTerms、RunSummary、RunTable、AlignmentGrid、DocumentBrowser 和 common 组件复用真实接口数据。Celery 的结果持久化后由前端轮询刷新。审阅前冻结主题快照以保持批准结果的可复查性。

`GET /runs` 只返回摘要（指纹、K、有效文档数、排除数、误差等），首页与队列不一次取回全量明细；`GET /runs/{id}` 返回完整词表与对齐；`GET /runs/{id}/documents?status=&reference=&page=` 按展签编号分页给出每次初始化的激活与排除原因，仅成功运行可用（进行中/失败返回 409）。`GET /documents` 同样分页。语料可 `POST /corpora` 建立后多次 `POST /corpora/{id}/batches` 追加（每批 1–1000 篇，批内与库内 reference 均不可重复）。逐篇明细只在全部分析成功后批量入库；任一环节失败即整体清除并标记 failed，失败运行不显示半份主题册。

## 验证与边界

真实容器/API/独立数值 oracle、seed 保修改、角色 403、真实浏览器导入到导出与截图结果见 `TESTING.md`。测试产物独立存放在批次 `test-artifacts/gb-0021`，不混入源码。主 fixture 的 360 篇与浏览器另外导入的 8 篇块状语料是两次不同研究；后者可分解到近零误差，不能据此声称真实语料同样可完美重建。流式管线在批大小 1/7/5000 下与原一次性计算逐位一致（H/W/指纹），重建误差差 ≤4e-15；百万篇合成语料五次初始化全程匿名内存峰值约 180MiB，低于 512MiB 上限。

当前面向已分词、固定领域白名单，未验证外部真实中文语料、跨领域泛化或生产并发。单批最多 1000 文档、同一语料分批追加至百万篇、10 次串行初始化，worker 并发 1、内存上限 512MiB、单任务软时限 2 小时；没有自动选 K、自动主题命名、在线增量词汇或外部发布。白名单会过滤未知词，编辑需核对原文。数值秩阈值及 NMF 容差会影响可拟合边界。元数据通过 SQLAlchemy create_all 创建，未提供生产迁移链。字体使用 Google Fonts，断网时退回本地衬线/无衬线字体。
